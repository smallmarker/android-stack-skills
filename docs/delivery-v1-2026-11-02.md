## 已实现并验证

- Python 3.11+ 可安装 CLI；version、recipes list、inspect、plan、install、verify、status、create、recover。
- YAML Recipe + Draft 2020-12 JSON Schema；严格模板、来源、版本、许可证、模板路径检查。
- Inspector：明确 Android 模块、Kotlin/Groovy、Catalog、namespace、minSdk、Compose/BOM、Hilt、现有依赖、Wrapper 与源码目录；未知值保留 unknown。
- Resolver：可读 / JSON 计划、统一 Diff、依赖复用与版本冲突、文件与 Kotlin 声明冲突、多模块选择、DI 适配信息、风险提示。
- Installer：dry-run、乐观并发检查、排他锁、私有事务日志、失败回滚、崩溃后恢复、文件哈希、版本和来源记录；不静默覆盖源码、不静默升级。
- Network：Retrofit / OkHttp / Gson、HTTPS、超时、Headers、TokenProvider/AuthInterceptor、ApiResult/ApiError/safeApiCall、错误映射、取消传播、Repository 示例、可选 Hilt Module。
- Image：Coil 3、共享 Loader、内存/磁盘缓存、AppImage、加载/错误插槽、Painter 占位/错误、圆角/圆形、ContentScale、contentDescription。
- Logging：Timber、AppLogger/Logger、等级与标签、debug/release、静态消息约束、动态字段白名单/Redacted、异常内容抑制、可选 Hilt。
- Lightweight / Standard：真实 Compose/MVVM 工程、Material 3 Theme、StateFlow 首页、可测试 Repository；Standard 的 Hilt 与接口/实现；两者复用同一套三个 Recipe。
- 官方 Gradle Wrapper JAR 及 distribution 均固定 SHA-256，附上游许可证；目标目录、名称、包名与符号链接保护。
- 四个完整 Skills 格式通过 quick_validate；CLI 工作流通过自动化测试。
- 双语 README、架构、协议、兼容性、测试、贡献、进度、许可和路线图文档。

## 创建演示

以下两条命令实际执行成功，示例保存在仓库 examples 中。先生成，再实际调用 verify，最后再次执行 verify 检查最终源码。

```sh
android-stack create --name LightweightDemo --package com.example.lightweight --preset lightweight --output examples/lightweight-app --skip-verify
android-stack create --name StandardDemo --package com.example.standard --preset standard --output examples/standard-app --skip-verify
android-stack verify --project examples/lightweight-app
android-stack verify --project examples/standard-app
```

两者实际调用的 Gradle 任务：`:app:assembleDebug :app:testDebugUnitTest --console=plain --stacktrace`。
结果均为 **BUILD SUCCESSFUL**。每个工程执行 13 tests、0 failures、0 errors、0 skipped。

APK 路径分别为 `examples/lightweight-app/app/build/outputs/apk/debug/app-debug.apk` 和 `examples/standard-app/app/build/outputs/apk/debug/app-debug.apk`，可用于后续设备验收；构建产物未提交 Git。

## 既有工程集成演示

真实矩阵脚本创建受控 fixture：保留现有匹配依赖，删除待集成 Recipe 的生成文件和安装记录，然后重新集成；其余业务与配置保留。

```sh
python scripts/verify_android.py --output /tmp/android-stack-acceptance-v1
```

Network / Image / Logging 三个场景实际分别执行引擎同一 plan → apply → verify 链路；CLI install 流程另外通过真实 subprocess 自动化测试。

| 场景 | 真实观察 |
|---|---|
| clean-compose | APK 构建通过，13 tests / 0 failures，重复安装不变 |
| existing-retrofit | 复用现有 3.0.0，不追加相同依赖；APK 与 13 tests 通过 |
| existing-coil | 复用现有 3.3.0；AppImage 编译、APK 与 13 tests 通过 |
| existing-timber | 复用现有 5.0.1；AppLogger 编译、APK 与 13 tests 通过 |
| existing-hilt | Standard/Hilt 构建通过，13 tests / 0 failures，重复安装不变 |
| version-conflict | 检出 Retrofit existing=2.9.0 / required=3.0.0，安装拒绝，文件哈希不变 |

冲突场景没有伪装成一次成功构建；它验证拒绝变更的正确性。所有通过构建的场景均在第二次安装后比较完整源码、配置和记录的哈希，再实际构建。

手工 CLI 对应命令：

```sh
android-stack inspect --project MyApp --json
android-stack plan --project MyApp --recipe retrofit-standard
android-stack install --project MyApp --recipe retrofit-standard --verify
android-stack install --project MyApp --recipe coil-standard --verify
android-stack install --project MyApp --recipe timber-standard --verify
android-stack status --project MyApp
```

已有 Hilt 项目需在安装后提供 NetworkConfig/TokenProvider binding，再 verify；已有 Application 的初始化需按 Usage.md 合并。未自动重写其生命周期代码。

## 尚未实现与限制

V1 边界内的核心 CLI/Recipe/生成器源码均已实现；上述宿主路由及设备人工验收尚未完成。不能据此宣称所有 V1 验收项已完成。

超出 V1 的功能未实现：Groovy 自动写入、AGP 9 built-in Kotlin、复杂 convention plugin / dynamic bundles / includeBuild / projectDir 自动改写、已有 ImageLoader 合并、自动升级/卸载、Token 自动刷新、XML/View 图片封装、跨框架迁移、云端平台和市场。

自由文本日志不具备“自动彻底脱敏”保证；设计通过静态消息、字段白名单和 release 默认静默控制数据入口。任意自定义 Gradle 程序无法仅靠静态扫描证明依赖兼容；明确支持范围之外应由 Agent 审查适配后执行真实构建。

Standard 构建有 kapt 对部分处理器参数的 warning，当前不影响 Hilt 编译或单元测试。没有删除测试或跳过构建来规避问题。
